## 一分钟了解这个项目

一个"模拟人"系统。每个**存档**就是一个独立的人格，有自己的记忆、情绪、身体、环境和人际关系，通过外部渠道和真实的人对话。

```
真实的人 ──外部渠道──> 模拟人（存档）──外部渠道──> 真实的人
                          │
                          ├─ 记忆：它记得什么
                          ├─ 性格：它是什么样（记忆的视图）
                          ├─ 情绪：它现在什么感觉
                          ├─ 生理：它身体怎么样
                          ├─ 环境：它在哪、周围什么
                          └─ 需求：它想要什么
```

两个进程：**cat**（Java，业务主体）· **跳板**（JS，DSH 插件）。

## 四条铁律

任何阶段都不许违反。

| # | 铁律 | 为什么 |
|---|---|---|
| **1** | **每一步都能跑通消息往返** | 真正的风险是"代码写了一堆、单测全绿，链路从没跑通过" |
| **2** | **一次只改一小块** | 方便定位问题 |
| **3** | **改完立刻验证** | 单测 + 手动 curl + 真实链路，都过了才进下一步 |
| **4** | **先跑起来，再谈架构** | 架构是给跑得通的东西用的 |

## 改文档的规则

| 情况 | 怎么办 |
|---|---|
| cat 代码改了，签名变了 | 改 `接口文档-cat.md` |
| 跳板代码改了 | 改 `接口文档-跳板.md` |
| 数据流变了 | 改 `图-数据流图.md` |
| 调用顺序变了 | 改 `图-时序图.md` |
| 加了新包/新类 | 改 `图-类关系图.md` |
| 设计了新概念 | 改 `架构总览.md` |
| 计划变了 | 改 `开发计划-短期.md` |
| 部署方式变了 | 改 `使用部署教程.md` |

**文档和代码冲突时，以代码为准，然后改文档。**

**唯一的例外**：`cat` 和 `dsh-wdd-cat-linker` 冲突时，以 `cat` 为准。
