## 一、入口

### `index.js` ✅

插件入口，只负责装配。

```js
export const name = 'dsh-wdd-cat-linker'

export const inject = [
  'agents', 'sessions', 'sessionTitle', 'timer', 'tools', 'workspaceRegistry'
]

export const Config = Schema.object({ ... })

export function apply(ctx, config)
```

**`Config` 的九个字段**（默认值全部取自 `DEFAULTS`）：

| 字段 | 类型 | 默认 |
|---|---|---|
| `enabled` | boolean | `true` |
| `catBaseUrl` | string | `http://127.0.0.1:8080` |
| `heartbeatIntervalMs` | number | `2000` |
| `inboundIntervalMs` | number | `2000` |
| `requestTimeoutMs` | number | `7000` |
| `logUploadLimit` | number | `50` |
| `outboundFailTtlMs` | number | `60000` |
| `systemPrompt` | string | `''` |

> `Config` 的 default **只在插件启动时生效**。用户之后在设置页改的值进 `LocalStore`，运行时必须用 `store.get(key)` 读。

**`apply()` 做的事**（按顺序）：

1. `settings = { ...Config(), ...(config || {}) }`
2. 建 `LinkerLogger`（同时打到宿主控制台）
3. 建 `Bridge` / `SessionFinder` / `MessageCache`
4. 建 `LocalStore` 并 `hydrate()`
5. 注册设置页路由（需要 `webServer` 服务）
6. 建 `Heartbeat` / `Inbound` / `Outbound`
7. 注册 `submit_replies` 工具
8. 注册日程工具拦截
9. 监听 `agent/created` 并补接管已在运行的 agent
10. 监听 `session/event`（出站）
11. 起三个 `ctx.interval`：心跳、拉队列、失败清理
12. 自执行块里立刻跑一次心跳

**三个定时器**：

| 周期 | 来源 | 做什么 |
|---|---|---|
| `heartbeatIntervalMs`（可配） | `settings` | `heartbeat.tick()` 然后 `inbound.setSessionIds()` |
| `inboundIntervalMs`（可配） | `settings` | `inbound.tick()` |
| **10000 固定** | `OUTBOUND_SWEEP_INTERVAL_MS` | `outbound.sweepFailed(store.get('outboundFailTtlMs'))` |

### `client.js` ✅

DSH 设置页，用 `window.__ModuleLoader__.load` 包装成浏览器模块。

**页面结构**：注册到插槽 `settings.section`，`id: 'wdd-cat-linker'`，`order: 54`。

**字段定义 `FIELDS`**（决定表单长什么样）：

| 分组 | 字段 | 控件 |
|---|---|---|
| 基本 | `catBaseUrl` | 文本框 |

| 节奏 | `heartbeatIntervalMs` / `inboundIntervalMs` / `requestTimeoutMs` | 数字 |

### `message_cache.js` ✅

三个池，全部按 `sessionId` 分桶。

```js
export class MessageCache { ... }
export const OutboundStatus = Object.freeze({ FLYING: 'FLYING', FAILED: 'FAILED' })
```

| 池 | 结构 | 用途 |
|---|---|---|
| `inbound` | `Map<sessionId, 消息>` | 入站拿到、尚未 ack |
| `pending` | `Map<sessionId, 消息>` | 已投进 DSH、等这一轮回复 |
| `outbound` | `Map<sessionId, 整轮记录>` | 已交卷、等推回 cat |

**入站池方法**：

```js
putInbound(message)      // 缺 sessionId 或 channelMessageId 时忽略
deleteInbound(message)   // ack 成功后清
hasInbound(sessionId)
peekInbound(sessionId)
inboundSize()            // 返回会话数（不是消息数）
```

**待应答池方法**：

```js
markPending(message)
takePending(sessionId)   // 取出并删除
peekPending(sessionId)   // 只看不取
pendingSize()
```

> **`peekPending` 是「这一轮是不是外部触发的」唯一判据**：`stateless_context` 和 `schedule_guard` 都用它。

**出站池方法**：

```js
putOutbound(sessionId, archiveId, messages, origin)   // 初始 status = FLYING
peekOutbound()                                        // 整张 Map
peekOutboundOf(sessionId)
deleteOutbound(sessionId)                             // 推成功
markOutboundFailed(sessionId)                         // 标 FAILED + 刷新时间
sweepFailedOutbound(ttlMs, now = Date.now())          // 返回被清掉的记录
outboundSize()
```

**整轮记录的形状**：

```js
{
  sessionId, archiveId, origin,
  messages: [{ chatType, chatId, text, index }],
  status: 'FLYING' | 'FAILED',
  updatedAt: number
}
```

### `session_finder.js` ✅

```js
export function sessionKey(id)      // 去掉 "session-" 前缀
export function shortId(id)         // 取末尾 8 位，日志用
export function idVariants(raw)     // 两种写法：["xxx", "session-xxx"]

**`allSessionIds()` 的四条路径**（合并去重）：

|---|---|---|
| ① | `sessionQuery.listSessions()` | 磁盘上所有会话，含没打开的 |

**`sessionTitle()` 的四条路径**（依次尝试）：

| # | 来源 | 前提 |
|---|---|---|
| ① | `sessionQuery.readTitle(id)` | 不要求会话活着 |
| ② | `sessionTitle.get(session)` | 需要活的 session 对象 |
| ③ | `sessions.get(id).title` | — |

`pickTitle()` 兼容三种返回形状：裸字符串、`{title}` / `{name}`、`{title: {title}}`。

**`resumeAgent()` 的关键**：

// 走 sessionController.agents.resolveAgent()，不是 agents.resume()

```

**服务缓存 `#service(name)`**：只缓存拿到的值——服务可能比插件晚就绪，把 `undefined` 缓存住就永远拿不到了。

**`SPEC`（内部常量）——配置项的唯一定义**：

| 键 | 类型 | 区间 | 默认 |
|---|---|---|---|
| `enabled` | bool | — | `true` |
| `catBaseUrl` | string | — | `http://127.0.0.1:8080` |
| `relayOutbound` | bool | — | `false` |
| `relayInbound` | bool | — | `false` |

| `requestTimeoutMs` | number | 1000~60000 | `7000` |
| `logUploadLimit` | number | 10~200 | `50` |
| `outboundFailTtlMs` | number | 5000~600000 | `60000` |

**`LocalStore` 方法**：

```js
constructor({ file, settings, log })
read()                 // 只认 EDITABLE_KEYS 里的键
hydrate()              // 启动时把 linker.json 覆盖进 settings
snapshot()             // 九个键的当前值
get(key)               // ✅ 已校正：夹取 + 非法退默认
save(incoming)         // → { changed, values }
```

**`get()` 的语义**（重要）：

```js
get(key) {
  const spec = SPEC[key]
  if (!spec) return undefined
  const value = normalize(key, this.settings[key], 'read')
  return value === undefined ? spec.default : value
}
```

返回值**保证落在 SPEC 区间内**，调用方不需要再自己夹一遍。这是"散落各处的 `Math.max/Math.min`"被收敛到一处的关键。

**`normalize(key, raw, mode)` 的两种模式**：

| 模式 | 字符串缺失时 | 用途 |
|---|---|---|
| `'save'` | 返回 `''`（清空是有意义的操作） | 用户提交 |
| `'read'` | 返回 `undefined`（让 `get` 退默认） | 运行时读取 |

**`registerRoutes(webCtx, store)`** 注册两个精确路由：

| 路由 | 方法 | 行为 |
|---|---|---|
| `/wdd-cat-linker/config` | GET | `{ok:true, values: snapshot()}` |
| | POST | `{ok:true, changed, values}`；body 非 JSON 返回 400 |
| `/wdd-cat-linker/style` | GET | 返回 `settings.css`，读不到返回 404 |

返回一个 `dispose` 函数用于卸载。

## 三、`linker/` HTTP 搬运

### `bridge.js` ✅

通往 cat 的唯一 HTTP 出口。

```js
export class BridgeError extends Error { }

export class Bridge {
  constructor({ baseUrl, timeoutMs = DEFAULTS.requestTimeoutMs })
  get(path)              // → 解析后的 JSON 或 null
  post(path, body)       // → 同上

```

| 行为 | 说明 |
|---|---|
| 超时 | `AbortController` + `setTimeout`，默认 7000ms，最小 500ms |
| 非 2xx | 抛 `BridgeError`，附带响应体前 300 字符 |
| 空响应体 | 返回 `null` |
| 非 JSON | 抛 `BridgeError` |
| `baseUrl` 为空 | 抛 `BridgeError('没有配置中转站地址')` |
| 尾部斜杠 | 构造时 trim 掉 |

### `heartbeat.js` ✅

```js
export class Heartbeat {
  constructor({ bridge, finder, logger, store, log })
  tick()       // single-flight
  dispose()
}
```

**`tick()` 的流程**：

1. 上一轮没跑完 → 直接复用上一轮的 Promise
2. `finder.getAllSessions()` → `Map<sessionId, title>`
3. `logger.recent(store.get('logUploadLimit'))` —— **每轮现读**，改设置下一跳生效
4. `POST /api/heartbeat`，body `{ sessions: {id: title}, logs: [...] }`
5. 成功：清单变了才打日志；失败：只打一次（`failed` 标志避免刷屏）

**对外暴露的状态**：`this.sessions`（最近一次算出的 Map）——`index.js` 用它给 `inbound.setSessionIds()` 喂数据。

### `inbound.js` ✅

```js
export class Inbound {
  constructor({ bridge, finder, cache, log })
  setSessionIds(sessionIds)
  tick()       // single-flight
  dispose()
}
```

**`tick()` 的流程**：

1. `sessionIds` 为空 → 直接返回
2. `GET /api/inbound_message/get?sessionIds=...`
3. 每条 `cache.putInbound(msg)` —— **先落池**
4. `POST /api/inbound_message/ack` —— **再 ack**
5. ack 成功后 `cache.deleteInbound(msg)`
6. 逐条 `deliver(this.deliverDeps, msg)` —— **最后投递**

**顺序的意义**：ack 在前意味着即使后面会话打不开，cat 那边也已推进水位——消息不会重投。代价是「会话不存在」时消息会丢，只记日志。

**`deliverDeps`** 在构造时建好：`{ finder, cache, log }`，不传整个 `Inbound` 实例。

### `outbound.js` ✅

```js
export class Outbound {
  constructor({ bridge, cache, log })
  submit(draft)                    // 工具交卷回调
  handleSessionEvent(session, event)
  push(sessionId, archiveId, messages, origin)   // → boolean
  sweepFailed(ttlMs)                              // → number
  dispose()
}
```

**`submit(draft)`**：把草稿存进 `drafts: Map<sessionId, draft>`。

草稿形状：

```js
{ sessionId, turn, replies: [{ chatType, chatId, text }] }
```

**`handleSessionEvent()`**：只处理 `event.type === 'turn/end'`。

**`#finishTurn()` 的四道判断**：

| # | 条件 | 不满足时 |
|---|---|---|
| 1 | `reason.kind === 'completed'` | 不发 |
| 2 | 有草稿且 `replies` 非空 | 不发 |
| 3 | `cache.takePending(sessionId)` 有值 | 不发（界面直接对话） |
| 4 | — | 通过则拼 messages 并 `push()` |

**messages 的拼法**：

```js
{ chatType: r.chatType || origin.chatType || '', chatId: r.chatId || origin.chatId || '', text, index }
```

**`push()` 的返回语义**：

| 返回 | 条件 |
|---|---|
| `true` | cat 回包里 `data.sessionId` 与本次一致 → 整轮删除 |
| `false` | 没拿到对应 ack / 网络异常 → 标 `FAILED` 留在池里 |

**`sweepFailed(ttlMs)`**：调 `cache.sweepFailedOutbound(ttlMs)`，对每条被删的记一条日志，返回删除条数。

**常量**：

```js
const SESSION_EVENT = { turnEnd: 'turn/end' }
const TURN_REASON = { completed: 'completed' }
```

> 宿主的事件名是封闭枚举，写错不报错、只静默不触发。

## 四、`utils/` 提示词与工具

### `deliver.js` ✅

一条来自 cat 的消息 → DSH 里的一轮提问。

```js
export function chatLabel(message)      // "群聊 20001，发送者 用户10002"
export function buildPrompt(message)    // → 提示词正文；正文为空返回 ''
export async function deliver({ finder, cache, log }, message)   // → boolean
```

**`buildPrompt()` 的输出形状**（固定）：

```
【来自外部聊天】群聊 20001，发送者 用户10002：
今天好累啊

（回复必须调用 submit_replies 工具，否则对方收不到。）
```

> 两条固定文案**硬编码在这个函数里**，不抽成常量：只此一处出现，改写时只动一个函数。

**`deliver()` 的三种丢弃**（都只记日志，不抛异常）：

| # | 条件 | 日志 |
|---|---|---|
| ① | 没有 `sessionId` | 「消息没有 sessionId，丢弃」 |
| ② | 正文为空 | 「消息正文为空，跳过」 |
| ③ | `resumeAgent()` 拿不到 agent | 「会话 …xxxx 打不开，丢弃这条消息」 |

> **② 在 ③ 之前**：空正文不值得为它恢复一次会话（恢复可能读磁盘）。

**成功路径**：

```js
await agent.followup({
  id: `${message.channelMessageId}-${message.archiveId}`,
  role: 'user',
  content: [{ type: 'text', text: prompt }],
  source: { kind: 'user' },
})
cache.markPending(message)
```

**返回值**：`true` 投进去了，`false` 被丢弃。

### `stateless_context.js` ✅

```js
export function takeOverSession(agentCtx, { systemPrompt, cache, log })
```

**接管一个会话，挂三组钩子**：

| 钩子 | 作用 |
|---|---|
| `systemPrompt.section({complete:true})` | 让人设成为模型实际收到的唯一 prompt 段 |
| `systemPrompt/assemble`（waterfall） | 把落盘的 `sections` 也换掉，保证日志与实际请求一致 |
| `agent/pre-step`（waterfall） | **判据 + 折叠本轮输入** |
| `session/event` | 提示词真正写进日志时触发抹历史 |
| `session/event`（内部） | 用 `queueMicrotask` 推迟 append |

**`agent/pre-step` 的逻辑**：

```
① step > 1        → 原样放行（工具调用的后续步骤）
② 取 user 消息     → 只收 source.kind === 'user'，滤掉 runtime-context
③ peekPending      → 没有 → 原样放行（界面直接对话）
④ 有 pending       → enter + 只留 user 文本，记录 anchor
```

**为什么只有 step 1**：工具调用会把一轮拆成多个 step，每步都抹会把上一步的工具结果一起抹掉。

**为什么用 `queueMicrotask`**：`session/event` 回调触发时 `entry.appending` 仍为 true，直接 append 会抛 `cannot reenter while another append is being published`。

**`wipeHistory(session, anchor, log)`**（内部）：

```js
// 从节点 1 开始（节点 0 是 system，不能碰），到 anchor 为止
session.append('user/message', makeUserMessage('[无状态] 更早的对话已丢弃。'), {
  surfaceOp: { op: 'replace', startSeq: history[0], endSeq: history[history.length - 1] },
  sourceEventSeqs: [...history],
})
```

**已知副作用**（代码注释里写明，接受这个代价）：

> 模型某轮没调用 `submit_replies` 交卷时，`pending` 会一直留着，那个会话里用户在界面上手打的对话也会被当成外部轮、历史被抹。

### `schedule_guard.js` ✅

```js
export function blockScheduleTools(ctx, cache, log)
```

**拦截的四个工具**：

```js
const BLOCKED_TOOLS = new Set([
  'schedule_create', 'schedule_list', 'schedule_update', 'schedule_delete'
])
```

**拦截逻辑**：

```js
ctx.on('tools/execute', async (exec, next) => {
  if (!BLOCKED_TOOLS.has(exec.name)) return next()
  if (!cache.peekPending(sessionId)) return next()      // 界面直接对话，放行
  return refusedResult(toolName)                         // 外部触发，拦截
})
```

**拒绝结果**：

```js
{
  content: [{ type: 'text', text: 'Error: ...（schedule_create 已拦截）' }],
  isError: true,
  error: { message: ..., info: { name: 'ScheduleToolBlocked', code: 'SCHEDULE_TOOL_BLOCKED' } }
}
```

**拒绝理由**（给模型看的原文）：

> 日程功能在这个存档里不可用：日程由外部中转站统一管理。如果对方让你记某件事或设提醒，直接用文字说明你记下了，不要试图调日程工具。

> 第一版**只拦截不转发**。完整形态应该是「拦截 → 转成内部渠道的消息 → 推回 cat 由它生成日程」。
