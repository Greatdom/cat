## 2. 第一次跑起来

### 2.1 启动 cat

```powershell
cd E:\程序代码\dsh\cat
mvn "-Dmaven.repo.local=E:\程序代码\dsh\.mvn-repo" spring-boot:run
```

> **注意**：PowerShell 会把 `-D` 参数吞掉，**必须加引号**。

**验证**：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
```

期望看到（中文在控制台可能显示为乱码，那是控制台编码问题，不是服务问题）：

```json
{
  "code": 200,
  "message": "ok",
  "data": "服务器运行中",
  "success": true
}
```

> **`/api/health` 只表示进程活着**，不反映渠道是否连通。渠道连通性要看日志。

### 2.2 启动模拟渠道服务（调试用）

**为什么用模拟服务**：真号接了有风控风险，调试阶段应该有个本地可控的替代品。

```powershell
cd E:\程序代码\dsh\target\qq
.\start.bat
```

**验证**：

```powershell
Invoke-WebRequest http://127.0.0.1:3000/ -UseBasicParsing
```

页面是三栏的聊天界面：左栏选以谁的身份发言，中栏会话列表，右栏聊天记录与输入框。

**模拟服务的两个机器人号**：

| token | 登录号 | 昵称 |
|---|---|---|
| `XXXXXX`（或空） | 10000 | 机器人10000 |
| `bot-10004` | 10004 | 机器人10004 |

其它 token → `403`。

**模拟服务里的用户**：10000 / 10001 / 10002 / 10003 / 10004，群号 20001。

> 这两个号在同一台服务上，靠 **token 区分**；请求带哪个 token，服务就以那个号的身份收发。

### 2.3 安装跳板到 DSH

**⚠ 最容易踩的坑**：DSH 加载的是**安装目录的实体副本**，不是源码目录。

```
源码   E:\程序代码\dsh\dsh-wdd-cat-linker
运行   D:\dsh\workspace\profiles\desktop\node_modules\dsh-wdd-cat-linker
```

**改完源码必须复制过去**（**先完全退出 DSH**，否则文件被占用）：

```powershell
$src = 'E:\程序代码\dsh\dsh-wdd-cat-linker'
$dst = 'D:\dsh\workspace\profiles\desktop\node_modules\dsh-wdd-cat-linker'

Copy-Item "$src\index.js"  "$dst\index.js"  -Force
Copy-Item "$src\client.js" "$dst\client.js" -Force
Copy-Item "$src\src\*"     "$dst\src\"      -Recurse -Force
Copy-Item "$src\locate\*"  "$dst\locale\"   -Recurse -Force
```

**如果源码里删了文件或移动了文件，安装目录也要跟着删**——`Copy-Item` 只增不删，残留的旧文件会和新的同名模块打架：

```powershell
# 例：某次把 utils/ 下的三个文件从 linker/ 移走了
Remove-Item "$dst\src\linker\submit_tool.js"         -Force -ErrorAction SilentlyContinue
Remove-Item "$dst\src\linker\stateless_context.js"   -Force -ErrorAction SilentlyContinue
Remove-Item "$dst\src\linker\schedule_guard.js"      -Force -ErrorAction SilentlyContinue
Remove-Item "$dst\src\linker\prompt_builder.js"      -Force -ErrorAction SilentlyContinue
```

**核对一下两边的文件树是否一致**：

```powershell
$src = 'E:\程序代码\dsh\dsh-wdd-cat-linker\src'
$dst = 'D:\dsh\workspace\profiles\desktop\node_modules\dsh-wdd-cat-linker\src'
Compare-Object (Get-ChildItem $src -Recurse -File | ForEach-Object { $_.FullName.Substring($src.Length) }) `
               (Get-ChildItem $dst -Recurse -File | ForEach-Object { $_.FullName.Substring($dst.Length) })
```

没有任何输出 = 两边一致。

> **`package.json` 不要整份覆盖**——安装目录那份由 pnpm 维护，含 `dependencies`。
> 但 `dsh` 段（bundle / client 声明）改了要手动同步。

**然后重启 DSH。**

**验证**：看 DSH 日志

```powershell
Select-String -Path 'D:\dsh\workspace\logs\desktop-next.log' -Pattern 'cat-linker' | Select-Object -Last 10
```

看得到跳板的日志行，就说明插件加载了。一次正常启动会看到：

```
[cat-linker] 无状态上下文已装载（agent/pre-step 等事件已注册）
[cat-linker] pre-step 进来：turn 1 step 1，N 条输入
[cat-linker] 心跳：报上 N 个可用会话
```

### 2.4 确认两边连上了

cat 收到心跳后会打：

```
心跳：可用会话 N 个，跳板日志 M 条
```

N > 0 表示跳板已经把会话清单报上来了。**N = 0 的话，存档页的会话下拉框会是空的。**

## 3. 配置存档

### 3.1 打开存档管理页

浏览器打开 **`http://127.0.0.1:8080/archives`**

页面上一张卡片 = 一个存档 = 一个模拟人。

### 3.2 建一个存档

1. 点「新建存档」
2. 填**存档名**（例：黑猫）。名字必须唯一
3. 选 **DSH 会话**——下拉框显示「会话名（sessionId）」
   - 候选来自跳板心跳上报，**列表为空说明跳板没连上**
   - 列表里没有也可以手填 `session-xxx`
4. 填**外部连接（Link）**，可以加多条：
   - 渠道（下拉，只列可用的外部渠道）
   - 账号（例：`10000`）
   - 地址（模拟服务是 `http://127.0.0.1:3000`）
   - Token（模拟服务 10000 用 `XXXXXX`，10004 用 `bot-10004`）
   - 设备 ID（只有硬件类渠道才用）
   - 启用勾选
5. 填**认识的聊天**：选渠道 + 类型（群聊/私聊）+ 号码，点「添加」
   - 只有这里列出的群和私聊，这个存档才会去拉消息
6. 点「保存」

**几个约束**（后端会校验，不满足直接报错）：

| 约束 | 报错 |
|---|---|
| 存档名唯一 | `存档名重复：xxx` |
| 同渠道账号唯一 | `账号重复：[external_qq:10000]` |
| 会话不与其他存档共享 | `会话已被其他存档占用：xxx` |
| 存档数不超上限 | `存档数量已达上限 N` |

> **Token 只进不出**：保存后页面不再显示它。编辑时留空 = 沿用原来的，不会把 token 抹掉。

### 3.3 验证链路

**第一步：看日志有没有拉到消息**

```powershell
Select-String -Path 'E:\程序代码\dsh\cat\data\logs\cat.log' -Pattern '拉到|收到' -Encoding UTF8 | Select-Object -Last 5
```

在模拟服务页面里用 10002 的身份在群里说一句话，期望看到：

```
存档 xxx 拉到 1 条（缓存 1）
```

**第二步：看跳板有没有投进 DSH**

```powershell
Select-String -Path 'D:\dsh\workspace\logs\desktop-next.log' -Pattern '收到 group|收到 private' | Select-Object -Last 3
```

期望：

```
[cat-linker] 收到 group:20001 → 会话 …a1b2c3d4：今天好累啊
```

**第三步：在 DSH 会话里看**

应该能看到一条带 `【来自外部聊天】` 前缀的用户消息。

**第四步：看回复有没有回到模拟服务**

在 DSH 里正常回复（模型会调 `submit_replies`），模拟服务的群里应该出现这句话。

```powershell
Select-String -Path 'E:\程序代码\dsh\cat\data\logs\cat.log' -Pattern '推回|发送失败' -Encoding UTF8 | Select-Object -Last 5
```

### 3.4 三个管理页 + 一个设置页

| 页面 | 地址 | 管什么 |
|---|---|---|
| 设置 | `/settings` | 4 项参数：QQ 收发间隔、合并窗口、合并条数、存档上限 |
| 存档 | `/archives` | 存档（会话 / 连接 / 认识的聊天） |
| 日志 | `/logs` | 两源日志合并：cat 自己的 + 跳板上报的 |
| 跳板设置 | DSH 侧边栏 →「黑猫工坊」 | 9 项：开关、地址、节奏、日志条数、失败保留时长 |

## 4. 日常开发流程

### 4.1 改了 cat

```powershell
# 直接重启即可（没配 DevTools，不会热更新）
cd E:\程序代码\dsh\cat
mvn "-Dmaven.repo.local=E:\程序代码\dsh\.mvn-repo" spring-boot:run
```

### 4.2 改了跳板

**必须**：退出 DSH → 复制 → 重启 DSH。见 [2.3](#23-安装跳板到-dsh)。

> 只改 `client.js`（设置页）**也要复制**，它同样是实体副本。
> **新加了目录**（比如 `src/utils/`）时，`Copy-Item -Recurse` 会自动建目录。

### 4.3 改了模拟服务

```powershell
# 1. 先关掉正在跑的模拟服务（否则 jar 被占用）
# 2. 打包
cd E:\程序代码\dsh\qq\qq
mvn "-Dmaven.repo.local=E:\程序代码\dsh\.mvn-repo" package "-DskipTests"

# 3. 部署
Copy-Item "target\qq-0.0.1-SNAPSHOT.jar" "E:\程序代码\dsh\target\qq\qq.jar" -Force
```

### 4.4 跑测试

```powershell
cd E:\程序代码\dsh\cat

# 全量
mvn "-Dmaven.repo.local=E:\程序代码\dsh\.mvn-repo" test

# 只跑某几个（注意：分隔符是逗号，不是加号）
mvn "-Dmaven.repo.local=E:\程序代码\dsh\.mvn-repo" test "-Dtest=ChatKeyTest,ContentTest"
```

**测试清单（9 个类，56 个用例）**：

| 测试类 | 用例数 | 测什么 |
|---|---|---|
| `ArchiveStoreTest` | 12 | 存档增删改查 + 五条校验 + 注册表三态 |
| `ArchivePersistenceTest` | 1 | 落盘后重启还能读出来 |
| `OneBotInboundConvertorTest` | 6 | 事件转换 + 过滤自己/别的存档 |
| `ConfigFieldBindingTest` | 7 | 配置项与字段的绑定关系 |
| `SnowflakeIdTest` | 4 | 唯一性、递增、越界拒绝 |
| `ChatKeyTest` | 8 | 解析往返、大小写、非法格式 |
| `ContentTest` | 8 | `plainText` 各种形态 |
| `MergeProcessorTest` | 7 | 合并窗口、最大条数、分桶隔离 |
| `MergeProcessorRealTimeTest` | 3 | 用真实时间戳验证合并 |

> `ArchivePersistenceTest` 会往真实 `cat/data/` 写文件，跑完自己清理。

### 4.5 常用调试命令

```powershell
# 健康检查（只表示进程活着）
Invoke-RestMethod http://127.0.0.1:8080/api/health

# 当前存档
Invoke-RestMethod http://127.0.0.1:8080/api/archives | ConvertTo-Json -Depth 5

# 存档页的候选（会话 + 可用渠道）——检查跳板有没有报会话上来
Invoke-RestMethod http://127.0.0.1:8080/api/archives/candidates | ConvertTo-Json -Depth 5

# 只看跳板报的日志
Invoke-RestMethod "http://127.0.0.1:8080/api/logs?limit=30&source=linker" | ConvertTo-Json -Depth 5

# 只看 cat 自己的日志
Invoke-RestMethod "http://127.0.0.1:8080/api/logs?limit=30&source=java" | ConvertTo-Json -Depth 5

# 当前设置
Invoke-RestMethod http://127.0.0.1:8080/api/settings | ConvertTo-Json -Depth 5

# 模拟服务里以某个身份说话
$utf8 = New-Object System.Text.UTF8Encoding($false)
$body = '{"chatKey":"group:20001","userId":10002,"text":"测试消息"}'
Invoke-WebRequest -Uri 'http://127.0.0.1:3000/sim/say' -Method Post `
  -ContentType 'application/json; charset=utf-8' -Body ($utf8.GetBytes($body)) -UseBasicParsing
```

> **PowerShell 的 `-D` 参数必须加引号**，否则会被拆成 `-D` + `.xxx`。
> **中文乱码**：控制台是 GBK，UTF-8 内容显示成乱码是正常的。
> 判断文件本身对不对：`[System.IO.File]::ReadAllText('路径', [System.Text.Encoding]::UTF8)`

## 5. 排障手册

### 5.1 消息进不来（外部发了，DSH 没反应）

按顺序查这三处：

| # | 查什么 | 怎么查 | 正常应该看到 |
|---|---|---|---|
| 1 | 跳板在不在报会话 | `GET /api/archives/candidates` | `sessions` 非空 |
| 2 | cat 有没有拉到消息 | `cat.log` 搜「拉到」 | `存档 xxx 拉到 N 条` |
| 3 | 跳板有没有投递 | DSH 日志搜「收到 group/private」 | `收到 group:20001 → 会话 …` |

**常见原因**：

| 现象 | 原因 | 修法 |
|---|---|---|
| `candidates.sessions` 为空 | 跳板没起来 / 插件没加载 | 看 DSH 日志有没有 `[cat-linker]` |
| 拉到了但没投递 | 存档绑定的会话打不开 | 存档页重选会话 |
| 完全没有「拉到」 | 存档没启用 / 连接没启用 / 认识的聊天为空 | 存档页检查 |

### 5.2 存档页的会话列表是空的

**原因**：跳板还没上报候选清单。

**修法**：
1. 确认跳板装好了（看 DSH 日志）
2. 等 2 秒（心跳间隔）
3. 刷新页面

### 5.3 会话显示的是短 id 而不是名字

**原因**：跳板取不到会话标题（DSH 还没给这个会话起名）。

**这是正常的**——新建的会话可能还没有标题，用几句话之后 DSH 会自动起名。

### 5.4 回复发不出去

**先分清卡在哪一环**：

| 检查 | 命令 | 说明 |
|---|---|---|
| 跳板有没有交卷 | DSH 日志搜「交卷」 | `交卷 N 条（会话 …）` |
| 跳板有没有推送 | DSH 日志搜「推回」 | `推回 cat N 条（存档 xxx）` |
| cat 有没有收到 | `cat.log` 搜「推回 N 条回复」 | `存档 xxx 推回 N 条回复` |
| cat 有没有发出 | `cat.log` 搜「发送失败」 | 没有这行就说明发出去了 |

**几个典型日志**：

| 日志 | 含义 |
|---|---|
| `这一轮由界面直接触发，不发到外部` | 正常——你在 DSH 界面上说的话不会外发 |
| `这一轮没有交卷内容，不发` | 模型没调 `submit_replies` |
| `推回 cat 失败（留在出站池待清理）` | cat 没起来或接口报错，这条会留一段时间后被清理 |
| `推回 cat 没拿到 ack` | cat 收到了但没确认（比如消息全空、存档不存在） |
| `发送失败 group xxxx：[send_xxx] ...` | 渠道后端连不上或拒绝 |
| `存档 xxx 没有 xxx 渠道的连接，这条发不出去` | 存档的连接被禁用或没配 |

### 5.5 一条消息被投递了两次

**查日志**：

```powershell
Select-String -Path 'E:\程序代码\dsh\cat\data\logs\cat.log' -Pattern '拉到' -Encoding UTF8 | Select-Object -Last 20
```

如果两条的 `存档 xxx` 是**不同的 id**，那是**抢话**（两个存档都认领了同一个群）——**这是设计行为**，不是 bug。

要避免：在存档页把其中一个存档的「认识的聊天」里这个群删掉。

如果两条是**同一个存档**，那是 at-least-once 的边界情况（见 [6. 已知边界](#6-已知边界)）。

### 5.6 控制台中文乱码

**这不是文件坏了**——PowerShell 控制台是 GBK，UTF-8 内容显示成乱码是正常的。

**判断文件本身对不对**：

```powershell
[System.IO.File]::ReadAllText('文件路径', [System.Text.Encoding]::UTF8)
```

### 5.7 改跳板不生效

**99% 是忘了复制**，或者**复制了但没删旧文件**。

```powershell
# 看安装目录的文件时间对不对
Get-Item 'D:\dsh\workspace\profiles\desktop\node_modules\dsh-wdd-cat-linker\src\*\*.js' |
  Select-Object Name, LastWriteTime | Sort-Object LastWriteTime
```

```powershell
# 对比两边文件列表是否一致（见 2.3 的 Compare-Object 片段）
```

### 5.8 设置改了不生效

| 在哪改的 | 生效时机 |
|---|---|
| cat 设置页（`/settings`） | **立即**——写回 `static volatile` 字段，读取方每次现读 |
| 跳板设置页（黑猫工坊） | 心跳、日志条数、失败保留时长都是**每轮现读**，下一跳生效 |
| 跳板设置页里的「地址」 | **要重启 DSH**——`Bridge` 只在插件启动时建一次 |

## 6. 已知边界

| 边界 | 说明 | 相关设置 |
|---|---|---|
| 入站是轮询 | 跳板默认 2 秒拉一次 | `inboundIntervalMs` |
| cat 侧也是轮询 | 每 500ms 一次 | 不可配（`TICK_MS`） |
| 两次轮询之间可能漏 | 单次拉取有上限 | `POLL_LIMIT = 20` |
| 投递是 at-least-once | 崩溃点不好时可能重复一次 | — |
| **无鉴权** | 只监听 `127.0.0.1`，不要暴露到局域网 | — |
| 发送失败不重试 | cat 侧「先出队再发」，失败即丢 | — |
| 出站推送失败会保留一段时间 | 过后丢弃，**当前不做重推** | `outboundFailTtlMs`（跳板） |
| 模型没交卷时 pending 会滞留 | 该会话里界面手打的对话也会被当成外部轮、历史被抹 | — |
| 入站图片不清理 | 会持续增长 | — |
| 模拟服务只支持两个机器人号 | `SimUsers.BOT_ACCOUNTS` | — |
| 模拟服务的会话记录是共享的 | 两个机器人看到同一份群记录 | — |

## 附录：日志往哪看

cat 同时往三个地方写日志，按需要选择：

| 去处 | 在哪看 | 用途 |
|---|---|---|
| 控制台 | 运行 `mvn` 的那个窗口 | 实时盯 |
| 滚动文件 | `cat/data/logs/cat.log`（按天切、单文件 20MB、留 7 天） | 事后查、能给工具搜 |
| 内存缓冲 | `http://127.0.0.1:8080/logs` 或 `GET /api/logs` | 和跳板日志合并看 |

**日志级别**统一由 `logback-spring.xml` 管，默认 `DEBUG`。要临时改：

```powershell
mvn "-Dmaven.repo.local=E:\程序代码\dsh\.mvn-repo" "-DCAT_LOG_LEVEL=INFO" spring-boot:run
```
