InboundService的handle方法从poller拉取到消息后存到缓存池供前处理器处理,每个前处理器维护一个缓存池,后一个前处理器将前一个处理器的结果作为输入
preprocessor目前有两个,根据不同渠道按不同策略处理:
第一个用于清除曾经已处理信息和水位下信息,特别是针对重启后的情况
第二个用于将几条消息合并成一条消息,规则如下:得到原始数据后先将数据按"存档:渠道:具体聊天"分桶进入不同的内部queue,
接着以一个原始信息为单位取出时间戳至今已有Tms的消息进行合并.
合并规则如下:一条合并后的消息包含能合并的按时间戳顺序排序的至多N条原始消息(包括在队列内的),相邻消息的时间间隔不大于Tms
最后的preprocessor将结果送给TriggerService处理

InboundMessageController是专门用于按具体会话分桶以队列限流投递消息之跳板并得到ack消息进而更新消息水位的Controller,将消息投递出去
......(经过跳板并得到回复,OutboundMessageController从跳板得到消息)
......后处理......(消息润色以及记账)
后处理之后将OutboundMessage传给OutboundService分发


链路中真正限流的地方有三处:第一处是poller按频率接收信息,第二处是InboundMessageController从队列群,按频率每个队列各自拿一条消息给跳板,再提高ack知道哪些消息已被处理,
第三处是sender从各自的队列按存档分桶的队列,按频率每个队列各自拿一条消息发送出去
