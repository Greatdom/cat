InboundService的handle方法从poller拉取到消息后存到缓存池供第一个前处理器处理,每个前处理器维护一个缓存池,后一个前处理器将前一个处理器的结果作为输入
preprocessor目前有两个,根据不同渠道按不同策略处理:
第一个用于清除曾经已处理信息和水位下信息,特别是针对重启后的情况
第二个用于将几条消息合并成一条消息,规则如下:得到原始数据后先将数据按"存档:渠道:具体聊天"分桶进入不同的内部queue,
接着以一个原始信息为单位取出时间戳至今已有Ams的消息进行合并.
合并规则如下:一条合并后的消息包含能合并的按时间戳顺序排序的至多N条原始消息(包括在队列内的),相邻消息的时间间隔不大于Tms
最后的preprocessor将结果送给TriggerService处理
......(经过各种链路,来到InboundMessageController)

......(经过跳板并得到回复,OutboundMessageController从跳板得到消息)
